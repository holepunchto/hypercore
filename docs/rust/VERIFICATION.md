# Reproducing verification

Test environment: Linux x86-64 (WSL), Rust/Cargo 1.98.1, Chromium 153.
A current stable Rust toolchain with a native linker is recommended. The declared
1.88 minimum reflects required language features; a separate 1.88 CI run has not
been performed. Windows-native and macOS builds have not been verified here.

## Verified results — 2026-09-30

- Formatting, strict workspace Clippy and native build: passed.
- **25 workspace tests:** 11 core integrity/persistence/bounds, 2 real JS11
  compatibility-fixture tests and 12 university database tests: passed.
- **3 vendored recovery regressions:** passed.
- **8 real process/API groups:** passed, including restart, public-key-pinned
  replication, actual read-only HTTP rejection and non-overwriting export.
- **15 browser groups:** passed on the final patched binary, with zero page-script
  errors and 11 screenshots. Responsive widths: 1440, 768 and 390 pixels.
- Native CLI `demo` created, audited, replicated, reopened and compared all six
  fictional projects successfully.
- Reverse interoperability: the original JS11 runtime verified all **14 events**
  exported by the final Rust API test writer. Its independently obtained public
  key came from the trusted local writer marker, not the imported bundle.

Local machine-specific logs/stores/screenshots are ignored under `artifacts/`;
reproduction scripts and the deterministic JS fixture are committed. The README
screenshot shows the real seeded Rust app. Automated GitHub CI is configured;
remote CI status is separate from these completed local results.

## Rust and persistence regressions

```sh
cargo fmt --all --check
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo test --locked --workspace
cargo test --locked --manifest-path vendor/hypercore/Cargo.toml \
  --no-default-features --features tokio,sparse --lib shadw_regression_tests
cargo build --locked -p university-demo
python3 tests/rust/api-smoke.py --binary target/debug/university-demo \
  --output artifacts/api-check
```

The API check requires a new output directory. It launches/stops real native
processes, exercises project commands and rejection cases, restarts the store,
replicates with an independently pinned public key, opens an actual reader, and
proves reader HTTP writes fail. Stores and logs remain under the specified
ignored artifact directory for inspection.

The vendored regressions exercise decoder flags, recovered append offsets and
trailing partial-entry recovery. Source/provenance is recorded in
[SHADW_PATCHES](../../vendor/hypercore/SHADW_PATCHES.md). They are bounded recovery
checks, not a general power-failure, filesystem-fault or formal-security audit.

## Real JavaScript compatibility oracle

The committed fixture was generated by the checked-out JavaScript Hypercore
**11.37.1**, with resolved crypto **3.7.0**, storage **3.3.1** and sodium **5.0.1**.
Its deterministic seed is deliberately public and test-only; never use it for
real data. Five signed compat-mode blocks cover empty, ASCII, UTF-8, binary and a
non-power-of-two forest. Independent tree/signature vectors cover lengths
0, 1, 2, 3 and 5. The generator verifies signatures and reconstructs a JavaScript
read-only replica before writing the fixture.

```sh
npm install --omit=dev --ignore-scripts --no-audit --no-fund
node scripts/rust/generate-js-fixtures.cjs
cargo test --locked -p shadw-core
```

Node's platform-specific prebuilt RocksDB/sodium dependencies must load; do not
claim oracle verification if the native addon fails. Linux may require the normal
`libatomic1` runtime. The Rust application does not depend on these JS tools.
The generator records actual package versions/provenance; dependency updates can
change metadata and should be reviewed explicitly.

For the other direction, export from a stopped native writer (or use the running
app's `/api/export`), obtain its public key separately, then run:

```sh
cargo run --locked -p university-demo -- export \
  --data ./data/university --output ./artifacts/rust-bundle.json
node scripts/rust/verify-rust-bundle.cjs \
  --bundle ./artifacts/rust-bundle.json --key <independently-obtained-public-key>
```

This executes JS11 `verifyFullyRemote` and `applyProof`, then compares every
available block. It is signed proof interoperability for explicit compat mode,
not a disk-format or Hyperswarm/Noise/protomux networking test. Non-compat manifest
v1 is captured as a separate reference, not advertised as supported.

## Browser workflows

Install Playwright in a separate test environment (not a runtime dependency),
and start the real Rust server against a disposable writable store:

```sh
cargo run --locked -p university-demo -- serve \
  --data ./artifacts/browser-writer --seed-demo --port 4192
node tests/rust/browser-smoke.cjs --url http://127.0.0.1:4192 \
  --output artifacts/browser-check
```

If needed, supply `PLAYWRIGHT_MODULE` with an installed Playwright module path
and `PLAYWRIGHT_CHROMIUM_EXECUTABLE` with an existing Chromium executable.
The script creates and archives one fictional QA project per run. It checks
1440/768/390-pixel layouts, real create/edit/archive/history, literal user text,
audit, public export, reload and disconnection recovery. Audit-failure and
read-only UI-state cases are explicitly injected responses; **actual** reader
write rejection is separately tested by `api-smoke.py`. No production user data
is required or used.

On this WSL host, browser profiles on the Windows-mounted project drive stalled
trusted click delivery; a temporary memory-backed browser profile worked.
Screenshots/reports and all project/toolchain/build data stayed on the intended
data drive. This is an environment-specific QA workaround, not an app dependency.
